# Внесок у проєкт

## Розробка

Вимоги: .NET 10 SDK і браузер Chromium, встановлений через Playwright, для ручного живого тестування.

```powershell
dotnet restore nzua-mcp.sln
dotnet test nzua-mcp.sln
pwsh bin/Debug/net10.0/playwright.ps1 install chromium
```

Для тестів парсера використовуйте синтетичні HTML-фікстури. Юніт-тести не повинні вимагати реального акаунта NZ.UA, сесії браузера чи мережевого доступу.

## Безпека даних

Ніколи не додавайте в коміт і не прикріплюйте реальний HTML журналу, HAR/HTTP-захоплення, cookies, значення CSRF, імена учнів чи вчителів, номери телефонів, ID конкретних шкіл, скріншоти, PDF, експорти аналітики чи журнали запитів.

Документуючи спостережений запит, залишайте лише HTTP-метод, відносний маршрут, назви полів і синтетичні тестові значення. Розглядайте всі незадокументовані маршрути NZ.UA як нестабільні внутрішні інтерфейси.

## Зміни

- Надавайте перевагу живим опціям форми над жорстко закодованими ID.
- Утримуйте write-інструменти в патерні read-before-write і verify-after-write.
- Зберігайте пакетні операції: кілька змін мають виконуватись одним викликом інструмента, а не циклом викликів.
- Не додавайте автоматичні рекомендації підсумкових оцінок.
- Тримайте приховування ПІБ увімкненим за замовчуванням.
- Додавайте цільові тести для кожної зміни парсера чи мутації.
- Запускайте `dotnet test nzua-mcp.sln` перед відкриттям pull request.
