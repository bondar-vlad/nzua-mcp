# nzua-mcp

Неофіційний локальний сервер Model Context Protocol для роботи вчителя з [NZ.UA](https://nz.ua/), побудований на .NET 10 та офіційному MCP C# SDK.

> [!IMPORTANT]
> Цей проєкт не пов'язаний, не схвалений і не підтримується NZ.UA, ТОВ «НЗ СОФТ», ІСУО чи Міністерством освіти і науки України. Він використовує спостережені внутрішні веб-маршрути, а не задокументоване публічне API NZ.UA. Маршрути та HTML можуть змінюватися без попередження.

Сервер уміє читати журнали та керувати уроками, темами, домашніми завданнями й оцінками. Він свідомо не генерує рекомендації підсумкових оцінок і не вгадує поточні ID НУШ/ГР.

## Безпека за замовчуванням

- **Лише читання:** записи в журнал заблоковані, доки не встановлено `NZUA_ALLOW_WRITES=true`.
- **ПІБ приховані:** учні показані як `Учень 1`, `Учень 2`, вчителі у списках заміни — як `Вчитель 1`, `Вчитель 2`, тоді як технічні ID лишаються доступними для викликів інструментів.
- **Лише ручний вхід:** облікові дані ніколи не запитуються через конфігурацію MCP чи змінні середовища.
- **Немає журналу запитів:** сервер не веде історію ваших змін ні в пам'яті, ні на диску.
- **Живі опції НУШ:** ID ГР та типів індексів беруться з поточної форми NZ.UA, а не з цього репозиторію.

Цей сервер працює з навчальними даними. Перед використанням реальних даних переконайтеся, що школа і провайдер моделі дозволяють таку обробку.

## Вимоги

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- Підтримуваний MCP-клієнт, наприклад VS Code з GitHub Copilot
- Встановлений Chromium для Microsoft Playwright

## Встановлення

```powershell
dotnet restore nzua-mcp.sln
dotnet build NzuaMcp.csproj
pwsh bin/Debug/net10.0/playwright.ps1 install chromium
```

VS Code може використати вже наявний [.vscode/mcp.json](.vscode/mcp.json). Еквівалентна конфігурація:

```json
{
  "servers": {
    "nzua": {
      "type": "stdio",
      "command": "dotnet",
      "args": ["run", "--project", "${workspaceFolder}/NzuaMcp.csproj"],
      "env": {
        "NZUA_ALLOW_WRITES": "false",
        "NZUA_PRIVACY_MODE": "redact",
        "NZUA_HEADLESS": "false"
      }
    }
  }
}
```

`NZUA_HEADLESS=false` корисне, якщо ви хочете, щоб fallback-браузер залишався видимим для діагностики або ручної перевірки. Для звичайної роботи сервер може працювати і з `true`; ручна автентифікація в будь-якому випадку відкриває видиме вікно. Почніть із `nzua_list_journals`. Якщо чинної сесії немає, автоматично відкриється видимий браузер. Пройдіть Cloudflare, увійдіть, оберіть потрібну школу/кабінет — вікно браузера залишиться відкритим і сервер повторно використовуватиме саме його для всіх подальших запитів (а не створюватиме новий headless-контекст щоразу). `nzua_session(action: "login")` може запустити той самий процес явно.

## Усунення несправностей

**Клієнт (Claude, Copilot тощо) відповідає "ця команда недоступна" замість виклику інструменту.** Це означає, що MCP-клієнт ще не бачить оновлений список інструментів — переважна причина: сервер (процес `dotnet`) запущено до перезбирання коду і не був перезапущений. Перезапустіть з'єднання з MCP-сервером (у VS Code: кнопка "Restart" у панелі MCP-серверів; у Claude Desktop — повністю перезапустіть застосунок), потім повторіть запит.

**Як перевірити, чи потрібен повторний вхід.** Викличте `nzua_session(action: "status")` — він показує чи є активна сесія в пам'яті сервера, скільки часу лишилось до її спливання і чи є збережена сесія на диску — без жодного мережевого запиту чи відкриття браузера.

**Сторінка nz.ua постійно показує "Performing security verification" / "Verify you are human".** Викличте `nzua_session(action: "logout")` — він закриває поточне вікно браузера і скидає сесію. Наступний виклик `nzua_session(action: "login")` **завжди** починає з абсолютно чистого профілю браузера (старі cookies, `cf_clearance` та локальне сховище видаляються автоматично перед кожним ручним входом) — тримати старий профіль сенсу немає: застарілий/недійсний `cf_clearance` частіше провокує Cloudflare показати перевірку знову, ніж допомагає її уникнути. Очищення профілю вбудовано в сам процес входу. Жоден із цих режимів не обходить Cloudflare автоматично — прапорець у видимому вікні браузера все одно потрібно поставити вручну. Якщо Cloudflare блокує саме вашу мережу/IP постійно, цей інструмент не допоможе — спробуйте іншу мережу.

**Не закривайте вікно браузера, яке відкрив ручний вхід.** Після успішного входу сервер навмисно тримає саме це вікно відкритим і повторно використовує його для всіх наступних запитів. Якщо закрити вікно вручну, наступний запит на читання автоматично відновить сесію й покаже зрозуміле повідомлення замість сирого тексту Playwright. Для записів (`nzua_set_marks`, уроки, домашні завдання) сервер не повторює запит автоматично в такому випадку (стан запису на сервері невідомий) — повідомлення явно каже перевірити результат вручну перед повтором.

## Конфігурація

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `NZUA_ALLOW_WRITES` | `false` | Встановіть `true`, щоб дозволити зміни оцінок, уроків і домашніх завдань |
| `NZUA_PRIVACY_MODE` | `redact` | Встановлюйте `full` лише в схваленому середовищі, щоб передавати реальні ПІБ |
| `NZUA_HEADLESS` | `true` | `true` = звичайний headless fallback; `false` = залишає браузер видимим для діагностики. Ручна автентифікація завжди відкриває видиме вікно |

Перезапустіть MCP-сервер після зміни змінних середовища.

## Інструменти

Сервер надає 9 інструментів.

| Інструмент | Призначення |
|---|---|
| `nzua_session` | `action`: `status` (без мережі), `login` (видимий браузер), `logout` |
| `nzua_list_journals` | Журнали, класи, предмети, семестри. `semesterId` перемикає семестр |
| `nzua_get_journal` | Учні, уроки, оцінки, теми й ДЗ — за один виклик |
| `nzua_get_form` | `kind`: `lesson` або `homework` — ID і поточні значення перед записом |
| `nzua_set_marks` | Виставлення оцінок |
| `nzua_add_lessons` | Додавання уроків (колонок) |
| `nzua_edit_lessons` | Зміна типу, дати, часу, кабінету (включно з перенесенням на іншу дату) |
| `nzua_delete_lessons` | Видалення уроків |
| `nzua_set_homework` | Тема, номер у плані, ДЗ, заміна |

### Один виклик замість багатьох

Інструменти спроектовані так, щоб модель не викликала їх у циклі:

- **Читання.** `/journal/index` повертає оцінки, теми й ДЗ на одній сторінці, тому `nzua_get_journal` тягне все разом і сам проходить усі сторінки пагінації. Щоб звузити вибірку, використовуйте `include`, `scheduleIds` або `studentIds` — фільтрація йде в пам'яті без нових запитів.
- **Запис.** Усі write-інструменти приймають `entriesJson` (або CSV для `nzua_delete_lessons`). 30 оцінок — це один виклик інструмента в одному браузерному сеансі, а не 30 викликів. В одному масиві можна змішувати різні уроки й різних учнів.

Спочатку прочитайте поточну форму/дані та перевірте змінені записи після кожного запису. Не налаштовуйте MCP-клієнт на автоматичне схвалення write-інструментів без перевірки.

## НУШ і ГР

Більшість журналів використовує звичайні оцінки 1–12 і окремих дій не потребує. Якщо ж у журналі є колонки ГР/НУШ, викличте `nzua_get_form(kind: "lesson", forNus: true)`. Це не "внутрішній мод" сервера, а живий запит до актуальної форми NZ.UA, який повертає поточні `lessonTypeId`, `nusLessonTypeId`, а також поточні значення форми для конкретного уроку.

Далі передайте ці ID разом із `forNus: true` у write-інструменти (`nzua_add_lessons`, `nzua_edit_lessons`, `nzua_set_homework` тощо). Сервер не містить власної кешованої таблиці НУШ-ID, не конвертує числові оцінки в рівні й не обчислює підсумкові/семестрові результати самостійно — ви можете робити це в клієнті окремо, а NZ.UA залишає свій офіційний розрахунок у себе.

## Тести

```powershell
dotnet test nzua-mcp.sln
```

Тестовий набір використовує синтетичні фікстури й покриває сувору обробку оцінок, визначення шкали, парсинг НУШ-форми, фільтрацію журналу в пам'яті, ручне відновлення сесії, приватність, зберігання, політику запису та поверхню MCP. Він ніколи не використовує реальний акаунт чи мережевий запит.

Живе smoke-тестування вимагає, щоб користувач вручну увійшов у систему, тому навмисно не входить до CI. GitHub Actions запускає тести на Windows і Linux.

## Чутливі локальні файли

- Сесія: `%APPDATA%\.nzua-session.json` у Windows
- Профіль браузера: `%LOCALAPPDATA%\nzua-mcp\playwright-profile` у Windows

Ставтеся до сесії та профілю браузера як до облікових даних.
